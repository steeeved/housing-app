# Build log: what each chapter added

Nyumba is a fictional housing listings site for a letting agency in Kenya. Each chapter is one branch and one pull request into `main`. All data is invented.

| Chapter | Branch | What it added |
|---|---|---|
| 1 | `course/chapter-01` | Nyumba homepage, edited with an AI agent |
| 2 | `course/chapter-02` | Git collaboration workflow and first deploy |
| 3 | `course/chapter-03` | Product plan: user stories, data notes, `AGENTS.md` |
| 4 | `course/chapter-04` | Listings page from one data file and a reusable card |
| 5 | `course/chapter-05` | Listing filters and an inquiry preview form |
| 6 | `course/chapter-06` | Server-side validation of the inquiry |
| 7 | `course/chapter-07` | PostgreSQL schema and seed |
| 8 | `course/chapter-08` | Drizzle ORM: listings read from the database, inquiries saved |
| 9 | `course/chapter-09` | Better Auth sign-in with a protected `/agent` page |
| 10 | `course/chapter-10` | Roles and agency isolation, `/dashboard` |
| 11 | `course/chapter-11` | `bun run check`, a check workflow, PR template, `docs/environments.md` |
| 12 | `course/chapter-12` | Validator with tests, calm failure pages, `react/no-danger`, `docs/break-list.md` |
| 13 | `course/chapter-13` | Launch check, launch checklist, README, demo script, retro, version 1.0.0 |

Green checks are necessary, not sufficient. They do not test phones, sign-in or who can see what.
